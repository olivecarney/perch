# Perch release and Proxmox deployment plan

Goal: install an embedded-assets, precompiled Perch binary into an unprivileged
Debian 13 LXC from the Proxmox host, and safely update it without touching data.
The user's requirements in this chat are the implementation specification.
Execution: inline, incrementally, as requested. No publication or host changes.

## Files and order

1. `.github/workflows/release.yml`: check Rust 1.98, tests, musl build, static
   linkage verification, HTTP tests outside checkout, deterministic archive and
   SHA256SUMS. Validate version tags against Cargo.toml. Publish only after checks.
2. `deploy/perch.service`, `scripts/install-native.sh`, `scripts/perch-update`,
   `scripts/release-common.sh`: root bootstrap, dedicated user, persistent data,
   minimal hardened service, shared release download and health checks. Archives
   contain these files plus binary and licenses; runtime uses no source/assets.
3. `scripts/proxmox/install.sh`: standalone interactive host entry point. Root/PVE
   and x86_64 checks; validate resources/network/storage; fetch and verify assets
   before creating a CT; Debian 13 template; no deletion of any CT on any path.
4. `tests/test_deployment.py`: exercise real shell functions with temporary paths
   and mocked external host/service commands. Reject corrupt artifacts; prove
   atomic update, rollback, data preservation, collision and input handling.
5. `README.md`: release prerequisite, one command, settings, backup/update/recovery,
   troubleshooting, uninstall and authentication limitations.

## Verification and review focus

- Run existing formatting, Rust tests, Clippy, release build, HTTP and logo tests.
- Run Bash syntax, ShellCheck and deployment tests; validate workflow with actionlint.
- Check failed/corrupt downloads never stop or replace the running binary.
- Check failed restart/health and interruption restore the old binary and service.
- Check existing IDs (including VMs), invalid network/storage and cancellation
  cannot create or destroy a CT; retain failed CTs for diagnosis.
- Check startup permits atomic writes in /var/lib/perch and no other writable
  application state; update never writes the collection or migrations.
- Real PVE lifecycle, Debian footprint and systemd hardening require host testing.
- No published releases at inspection (GitHub API returned []); workflow must land
  and a version tag must finish publishing before the installation command works.

## Completion record

All five implementation steps are complete locally. Final verification passed:
8 Rust unit tests, 6 HTTP integration tests, 4 JavaScript tests, 19 deployment
transaction/input/archive tests, cargo fmt, Clippy, release build, Bash syntax,
ShellCheck, actionlint and tracked-diff whitespace checks. Local Rust is 1.99.1
on macOS; the minimum 1.98 Linux musl build is enforced by CI, not tested here.

An independent review identified the need for nesting=1 for systemd filesystem
isolation inside PVE. The installer now sets this explicitly; regression tests
verify both nesting and unprivileged creation, and the README explains the tradeoff.
Targeted follow-up review passed with no outstanding actionable findings.

No commits/tags were pushed and no releases published. First CI publication,
real PVE lifecycle (including boot), systemd confinement and default memory/disk
measurement remain deployment validation steps for a real host.
